# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

The pet plugin tracked 0.2.1-rc.3 while the supported host moved to 0.2.2-alpha.3. Besides the cohort and Node-floor change, the new Cordis event typings reject the extension-page helper's broad string subscription signature, and the freshly resolved Cosmokit needs a matching release-age entry.

## Decision

SDK development dependencies move to `^0.2.2-alpha.3`, Cordis to `~4.0.6-alpha.2`, and schemastery to `~3.18.6-alpha.2`; the host engine and peer floors are `>=0.2.2-alpha.3`. CI runs Node 24.9.0. The lockfile, release-age ledger, README badges and pairing hashes move together.

The extension-page context accepts the host's generic event method through erased parameter types and casts the subscription at the call site. Runtime behavior is unchanged: the page still reconciles once per `slots/changed` event. Cosmokit is excluded at its resolved `1.8.7-alpha.2` version.

## Alternatives considered

**Keep the string event signature.** Rejected: it is not structurally compatible with the new generic Cordis `on` method, so the client no longer typechecks even though the event name and payload are unchanged.

**Suppress the release-age failure globally.** Rejected: the exclusion remains scoped to the exact resolved Cosmokit version rather than disabling the policy.

**Publish a new pet package as part of the cohort move.** Rejected: no release was requested and the package version stays unchanged.

## Consequences

Frozen installation passes the supply-chain policy check. Typecheck, the complete Vitest suite and the build pass. The pet plugin keeps its existing UI and runtime behavior, with host Node 24.9 or later required. No package is published to npm; dsh-web consumes the updated working-tree content through its normal satellite workflow.
