# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

## Problem

The pet plugin tracked 0.2.2-alpha.3 while the supported host moved to the published 0.2.2-rc.1 cohort (with Cordis 4.1.0, schemastery 3.19.0 and Cosmokit 1.9.0). Declarations, lockfile resolutions and release-age exclusions must advance together so local and CI checks validate against the shipped release candidate.

## Decision

SDK development dependencies move to `^0.2.2-rc.1`, Cordis to `~4.1.0`, and schemastery to `~3.19.0`; the host engine and peer floors move to `>=0.2.2-rc.1`. The lockfile, release-age exclusion ledger (replacing alpha.3/alpha.2 entries with exact 0.2.2-rc.1 and stable vendor versions), README badges and bilingual pairing hashes move together. Runtime and UI behavior are unchanged because the `dsh-v0.2.2-rc.1` source tree matches `dsh-v0.2.2-alpha.3`.

## Alternatives considered

**Keep alpha.3 ranges and rely on semver satisfaction.** Rejected: tilde pins on `4.0.6-alpha.2` and `3.18.6-alpha.2` would prevent resolving Cordis 4.1.0 and schemastery 3.19.0, splitting the cohort from the 0.2.2-rc.1 host.

**Publish a new pet package version.** Rejected: no release was requested and the package version remains unchanged.

## Consequences

`pnpm install --frozen-lockfile --ignore-scripts` passes supply-chain policy verification. All 22 migration/CLI script tests, `pnpm typecheck`, the full Vitest suite and `pnpm build` pass. No package is published to npm; dsh-web consumes the rebuilt working tree through its satellite profile link.
