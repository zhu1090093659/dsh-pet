宠物插件随 dsh-web 家族对齐到统一版本 0.4.14，本次只搬版本号：本仓自 v0.4.13 发布以来在 `v0.4.13..HEAD` 区间内只有一条决策记录提交（`.agents/notes` 下的评审记录），没有任何代码或资产改动，0.4.14 是一次纯粹的家族对齐发布。

> **兼容性**：没有破坏性变更，也无需手工迁移。包名 `@linxin666/dsh-pet` 与安装方式不变；持久化标识不变（布局与游戏进度仍写在 `$DSH_HOME/pet.json`，键名一个不改；宠物资产仍落在 `$DSH_HOME/pets/<id>/`；语音包分层仍是宠物 `voice.json` > 全局 `$DSH_HOME/pets/.voice.json` > 内置）；状态装饰目录与 `decoration.json` 契约不变；线协议字段与设置字段名（`petId`、`statusBubbles` 等）不变；`dsh.engines.dsh` 的声明与下限本轮同样不动，仍是 `>=0.2.1-rc.3`，`@deepseek-ai/dsh` 的 peer 依赖下限亦不变。因此 0.4.13 的安装可以直接升级，回退到 0.4.13 也不需要迁移数据。

### 其他改动

- 版本对齐：`package.json` 的 `version` 从 0.4.13 抬到 0.4.14，只为跟随 dsh-web 家族的统一版本号（卫星先发、主仓后发），没有功能、测试、契约或资产的改动
- 决策记录：新增 `.agents/notes/implemented/process/2026-11-01-review-round.md`，记录本轮三只宠物 PR（#26 live2d 换肤与呼吸、#23 红鲸少女内容、#20 frames2d 玩法层）的评审结论：零合并，#26 因五处未被测试覆盖的运行时、schema 与架构缺陷退回修改，#23 与 #20 维持原状；该提交只动 `.agents/notes`，不改代码、契约或资源

- 行为不变量：亲和度积分、奖励、冷却与已持久化的账本、宠物渲染与拖拽位置、设置表单与公告位、配对信任围栏都与 0.4.13 完全一致；本说明文件不在 npm 包的 `files` 白名单里，不会进入发布产物

This release aligns the pet plugin with the unified dsh-web family version and moves nothing but the version number: across `v0.4.13..HEAD` this repository carries a single decision-record commit (a review record under `.agents/notes`) and no change to code or assets, so 0.4.14 is a pure family alignment.

> **Compatibility**: nothing breaks and no manual migration is needed. The package name `@linxin666/dsh-pet` and the install path are unchanged; every persistence identifier keeps its name (layout and gameplay progress still live in `$DSH_HOME/pet.json` with identical keys, pet assets still land in `$DSH_HOME/pets/<id>/`, and voice-pack layering is still pet `voice.json` > global `$DSH_HOME/pets/.voice.json` > built-in); the status-decoration directory and the `decoration.json` contract are unchanged; wire-protocol fields and the settings field names (`petId`, `statusBubbles` and the rest) are unchanged; and the `dsh.engines.dsh` declaration and its floor stay untouched this cycle at `>=0.2.1-rc.3`, as does the `@deepseek-ai/dsh` peer floor. An existing 0.4.13 installation can upgrade in place, and going back to 0.4.13 needs no data migration either.

### Other Changes

- Version alignment: `version` in `package.json` moves from 0.4.13 to 0.4.14 purely to follow the unified dsh-web family version (satellites ship first, the main repository follows), with no functional, test, contract or asset change
- Decision record: `.agents/notes/implemented/process/2026-11-01-review-round.md` records the verdicts on this round's three pet PRs (#26 live2d skin swapping and breathing, #23 red whale girl content, #20 frames2d gameplay layer): zero merges, #26 returned for changes over five runtime, schema and architectural defects the test suite does not cover, and #23 and #20 left in their previous states; that commit touches `.agents/notes` only, with no code, contract or asset edit
- `src/` and `assets/` are byte-identical to 0.4.13: no commit in the interval touches them, so the only difference in the published artifact comes from one version string baked in at build time: `buildPackageVersion()` in `shared/tsdown.client.ts` reads `manifest.version` and injects it as `__DSH_PKG_VERSION__` for the anonymous install heartbeat, so the baked value changes from 0.4.13 to 0.4.14 while the minified module bodies, the export tables and the type declarations stay the same
- No committed artifact moves with it: `lib/` is not tracked (it sits in `.gitignore`) and is rebuilt on the spot by the `prepare` script at publish time, so this commit contains only `package.json` and this file
- Behaviour invariants: affinity points, rewards, cooldowns and the persisted ledger, pet rendering and dragged positions, the settings form and the announcement slot, and the pairing trust fence are all identical to 0.4.13; this notes file is outside the npm package's `files` whitelist and never reaches the published artifact
