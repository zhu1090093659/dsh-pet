宠物插件随 dsh-web 家族对齐到统一版本 0.4.16。本区间 `v0.4.15..v0.4.16` 只有一条代码提交和两条文档提交：内置 `whale-girl-refined` 的两行跑动帧被重新绘制，消掉腰侧那只看起来凭空长出来的手（观感上读作三条手臂），并补上一个只读图集几何的回归测试；其余两笔是 2026-11-05 两轮宠物工作的决策记录。没有新增宠物、没有新增设置项，渲染器、游戏逻辑、线协议字段与持久化标识一个都不动。

> **兼容性**：没有破坏性变更，依赖、peer 与 engines 一行未改——`dsh.engines.dsh` 仍是 `>=0.2.2-rc.1`，`@deepseek-ai/dsh` 的 peer 下限与 `engines.node`（`>=24.9.0`）同样不动，停在 0.4.15 的安装可以直接升上来，也可以直接退回去，两个方向都不需要迁移数据。包名 `@linxin666/dsh-pet` 与安装方式不变；持久化标识不变（布局与游戏进度仍写在 `$DSH_HOME/pet.json`，宠物资产仍落在 `$DSH_HOME/pets/<id>/`，语音包分层仍是宠物 `voice.json` > 全局 `$DSH_HOME/pets/.voice.json` > 内置）；状态装饰目录与 `decoration.json` 契约不变；`assets/whale-refined/pet.json` 一个字节没动，图集的列数、行序、每行帧数与两行跑动的时长表都保持原值，所以升级改的是内置鲸鱼娘跑动两行的像素，不是任何调用方读到的清单。

### 修复

- 内置 `whale-girl-refined` 的跑动两行重绘（issue #2021）：`assets/whale-refined/spritesheet.webp` 是单张 1536x1872 图集，8 列 x 9 行、单元格 192x208，行 1 是 `running-right`、行 2 是 `running-left`。两行原先取自同一个四分之三侧身跑姿，远侧手臂被单独画了一次，白色袖口与肤色手掌压在腰侧的裙子上，而连接它的袖子与裙子同为深藏青、看不出连接，于是袖口与手掌像是凭空长在腰上：在 192x208 的大屏预览上还算克制，在宠物实际渲染的 148x160 单元格（`display.size: 160` 对 208 高的单元格，经 `scaledCellSize` 缩放）上直接读成三条手臂。八个跑动帧里七个带这个缺陷，帧 3（列索引 2）的手几乎完全被裙子挡住，只需要小幅清理
- 改法是逐格擦掉那处袖口、手掌与深色描边，用调和（Laplace）插值重建其下的裙子，再把结果吸附到从裙子一侧环形采样得到的调色板，保持原作平涂藏青的质感而不是抹出一片渐变；近侧胸前的手臂、躯干、荷叶领、围裙与跑动剪影一个字不改。行 2 不再单独重绘，而是逐格取行 1 的水平镜像，两行从此不可能各自漂移，顺带也消掉了旧行 2 以 x=95 而非 x=191 镜像留下的 1 像素偏移
- 其余行不动：行 0 与行 3 至 8 的像素保持不变，唯一差异是 `alpha: 0` 处的 RGB 值（libwebp 无损编码会把这些颜色归零），任何渲染器都显示不出这类像素
- 容器仍是无损：图集按 VP8L 重编码并置位 alpha 标记，每个姿势周围的透明留白在 alpha 通道上保留，不会出现相邻帧串色的边；文件体积因为重绘去掉了部分高频细节，从 2199642 字节变为 2186206 字节，解码后的画布尺寸不变
- 清单不动：`assets/whale-refined/pet.json` 未修改——没有引入 `cell` 覆盖（那会把全部九行一起重新缩放，而不只是重绘的两行），`spritesheetPath` 仍是 `spritesheet.webp`，`frames` 仍是 9 行，两行跑动的 `durations` 完全一致

### 其他改动

- 图集几何回归测试：新增 `tests/whale-refined-atlas.spec.ts`（118 行），断言一个无依赖的检出就能从文件头与清单读到的那一半契约——画布正好是 8x9 个 192x208 单元格且无裁切或补边、清单停在默认单元格、两行跑动每列一帧且共用同一节奏、没有任何轨道的时长表长于它播放的行、容器仍是带 alpha 的 VP8L（RIFF / WEBP / VP8L 头、14 位宽高、alpha 与版本位）。像素级的那一半（跑动两行以外的行逐像素不变、行 2 是行 1 的精确镜像）在改动落地时用外部解码器对改动前的图集比对过，结论写在同批提交的决策记录里，测试文件头写明了这层分工
- 决策记录：新增 `.agents/notes/implemented/bug-fix/2026-11-06-whale-refined-third-arm-in-run-rows.md`（100 行），记录问题、擦除与镜像的做法、被否掉的替代方案（只把远侧袖子调深、从同帧拷贝裙子补丁、平涂单色、整轮重画、砍掉跑动帧改用行 7、放大图集或改单元格尺寸）与后果
- 文档：区间内的两笔 `docs(notes)` 提交把 2026-11-05 的宠物 intake 与傍晚评审两轮记录写进 `.agents/notes/implemented/process/2026-11-05-pet-intake-round.md`，不涉及代码与产物
- 版本对齐：`package.json` 的 `version` 从 0.4.15 抬到 0.4.16，跟随 dsh-web 家族的统一版本号（卫星先发、主仓随后跟上同号：本仓 0.4.16 发出时父仓仍停在 0.4.15，等它的集成提交把版本抬到 0.4.16）。构建期唯一随之变化的是 `shared/tsdown.client.ts` 的 `buildPackageVersion()` 经 `__DSH_PKG_VERSION__` 烙进匿名安装心跳的那个值，压缩后的模块体由上面的代码提交决定
- 发布提交只含 `package.json` 与本文件：`lib/` 不入库（在 `.gitignore` 里），发布时由 `prepare` 脚本现场重建，所以本次没有已提交的构建产物需要刷新；本文件不在 npm 包 `files` 白名单里，不会进入发布产物
- 行为不变量：宠物渲染与拖拽位置、亲和度积分、奖励、冷却与已持久化的账本、设置表单与公告位、配对信任围栏、注册表扫描语义都与 0.4.15 完全一致；`src/` 逐字节未改，`assets/` 里除 `assets/whale-refined/spritesheet.webp` 外的文件逐字节相同，`contracts/` 一个字节没动

This release aligns the pet plugin with the unified dsh-web family version 0.4.16. Across `v0.4.15..v0.4.16` there is one code commit and two documentation commits: the two run rows of the built-in `whale-girl-refined` pet are repainted so the hand that seemed to grow out of the waist (a pose the eye reads as three arms) is gone, plus a regression test that reads only the atlas geometry; the other two commits record the 2026-11-05 rounds of pet work. No pet is added, no setting is added, and the renderers, gameplay logic, wire-protocol fields and persistence identifiers are untouched.

> **Compatibility**: nothing breaks, and no dependency, peer or engine line moves - `dsh.engines.dsh` stays `>=0.2.2-rc.1`, the `@deepseek-ai/dsh` peer floor and `engines.node` (`>=24.9.0`) stay as they were, so an installation on 0.4.15 upgrades and rolls back without any data migration in either direction. The package name `@linxin666/dsh-pet` and the install path are unchanged; every persistence identifier keeps its name (layout and gameplay progress still live in `$DSH_HOME/pet.json`, pet assets still land in `$DSH_HOME/pets/<id>/`, and voice-pack layering is still pet `voice.json` > global `$DSH_HOME/pets/.voice.json` > built-in); the status-decoration directory and the `decoration.json` contract are unchanged; `assets/whale-refined/pet.json` is byte-identical, so the column count, row order, per-row frame counts and both run-row cadences keep their values - what the upgrade changes is the pixels of the two built-in run rows, not any manifest a consumer reads.

### Bug Fixes

- Both run rows of the built-in `whale-girl-refined` pet are repainted (issue #2021): `assets/whale-refined/spritesheet.webp` is one 1536x1872 atlas, 8 columns x 9 rows of 192x208 cells, with row 1 as `running-right` and row 2 as `running-left`. Both rows were drawn from one three-quarter side pose and the far arm was drawn a second time: its white cuff and skin hand sat on the dress at the waist, and the sleeve connecting it is the same dark navy as the dress, so no join is visible. The cuff and hand arrive with no arm attached and the eye reads them as a pale hand growing out of the waist - restrained at 192x208 on a large screen, unmistakable at the 148x160 cell the pet actually renders at (`display.size: 160` over a 208-tall cell, through `scaledCellSize`), where the pose counts three arms. Seven of the eight run frames carried the defect; frame 3 (column index 2) had the hand almost entirely hidden behind the dress and needed only a small cleanup
- The repair erases that cuff, hand and its dark contour in every cell, reconstructs the dress beneath with a harmonic (Laplace) interpolation, and snaps the result to a palette sampled from an annulus on the dress side of the hole, so the fill keeps the artwork's flat navy tone instead of smearing a gradient across it; the near arm at the chest, the torso, the ruffled collar, the apron and the running silhouette are untouched. Row 2 is no longer repainted on its own: every `running-left` cell is the exact horizontal mirror of the matching `running-right` cell, so the two rows cannot drift apart again - which also removes the one-pixel offset the old row 2 carried by mirroring about x=95 instead of x=191
- Every other row is untouched: rows 0 and 3-8 keep their pixels, and the only differences in them are RGB values under `alpha: 0`, where libwebp lossless zeroes colour it does not need. No renderer can show them: a transparent pixel contributes nothing to the composite whatever its RGB
- The container stays lossless: the atlas is re-encoded as VP8L with the alpha flag set, so the transparent padding around each pose survives in its alpha channel and no frame bleeds into its neighbour. The file shrank from 2199642 to 2186206 bytes because the repaint removed some high-frequency detail; the decoded canvas is the same size
- The manifest does not move: `assets/whale-refined/pet.json` is unmodified - no `cell` override was introduced (that would rescale all nine rows, not just the two repainted ones), `spritesheetPath` is still `spritesheet.webp`, `frames` still lists 9 rows, and both run rows declare identical `durations`

### Other Changes

- Atlas geometry regression test: `tests/whale-refined-atlas.spec.ts` is new (118 lines) and pins the half of the contract a dependency-free checkout can read from the file header and the manifest - the canvas is exactly 8x9 cells of 192x208 with no trimmed or padded margin, the manifest stays on the default cell, both run rows fill every column with one shared cadence, no track declares more durations than its row has frames, and the container is still lossless VP8L with alpha (RIFF / WEBP / VP8L header, 14-bit width and height, alpha and version bits). The pixel-level half (every row other than 1 and 2 unchanged, row 2 the exact mirror of row 1) was verified with an external decoder against the pre-fix atlas while the repaint landed; the result is written up in the decision record that ships in the same commit, and the spec header states that split
- Decision record: `.agents/notes/implemented/bug-fix/2026-11-06-whale-refined-third-arm-in-run-rows.md` is new (100 lines) and records the problem, the erase-and-mirror method, the rejected alternatives (only darkening the far sleeve, patch-filling from the same frame, a flat single colour, redrawing the whole cycle, dropping the run frames in favour of row 7, scaling the atlas or changing the cell) and the consequences
- Documentation: the two `docs(notes)` commits in this range record the 2026-11-05 pet intake and evening review rounds in `.agents/notes/implemented/process/2026-11-05-pet-intake-round.md`, with no code or artifact change
- Version alignment: `version` in `package.json` moves from 0.4.15 to 0.4.16 to follow the unified dsh-web family version: satellites ship first and the main repository follows to the same number (the parent still sits on 0.4.15 when 0.4.16 ships here, and its integration commit lifts it to 0.4.16). The only thing build time derives from it is the value `buildPackageVersion()` in `shared/tsdown.client.ts` injects as `__DSH_PKG_VERSION__` for the anonymous install heartbeat; the minified module bodies are determined by the code commit above
- The release commit contains only `package.json` and this file: `lib/` is not tracked (it sits in `.gitignore`) and is rebuilt on the spot by the `prepare` script at publish time, so no committed build artifact needs refreshing; this notes file is outside the npm package's `files` whitelist and never reaches the published artifact
- Behaviour invariants: pet rendering and dragged positions, affinity points, rewards, cooldowns and the persisted ledger, the settings form and the announcement slot, the pairing trust fence and the registry scan semantics are all identical to 0.4.15; `src/` is byte-identical, every file under `assets/` other than `assets/whale-refined/spritesheet.webp` is byte-identical, and `contracts/` is untouched.
