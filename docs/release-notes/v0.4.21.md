宠物插件随 dsh-web 家族对齐到统一版本 0.4.21，与全家桶同版本发布。本区间 `v0.4.20..HEAD` 没有任何提交：0.4.21 是一次纯版本对齐，`src/`、`assets/`、`contracts/`、`locale/`、`shared/`、`tests/` 与 `scripts/` 相对 0.4.20 一个字节没动，运行时行为、依赖、导出面与持久化契约全部不变，唯一的差别是版本号本身。

> **兼容性**：没有破坏性变更；`dsh.engines.dsh` 与 peer、engines 下限仍是原值，包名、导出面、持久化标识与线协议均未改，0.4.20 可直接升上来，也可直接退回，两个方向都不需要迁移数据。

### 其他改动

- 版本对齐：`package.json` 的 `version` 从 0.4.20 改为 0.4.21，卫星先发、主仓随后跟上同号。
- 构建期唯一随版本变化的烙入值：`shared/tsdown.client.ts` 的 `buildPackageVersion()` 读取 `package.json` 的 `version`，并作为 `__DSH_PKG_VERSION__` 烙进匿名安装心跳，烙入值从 0.4.20 变成 0.4.21；模块体、导出表与类型声明由未改动的源码决定，与 0.4.20 一致。
- 发布产物：`lib/` 仍不入库（在 `.gitignore` 里），发布时由 `prepare` 脚本现场重建；本文件不在 npm 包 `files` 白名单里，不会进入 tarball。
- 本次发布提交只有 `package.json` 与 `docs/release-notes/v0.4.21.md`。

<summary>English</summary>

Pet plugin aligns to the unified family version 0.4.21 and ships together with the family. The range `v0.4.20..HEAD` holds no commits at all: 0.4.21 is a pure version alignment, `src/`, `assets/`, `contracts/`, `locale/`, `shared/`, `tests/` and `scripts/` are byte-for-byte identical to 0.4.20, and runtime behaviour, dependencies, export surface and persisted contracts are all untouched - the version number is the only difference.

> **Compatibility**: no breaking changes; the `dsh.engines.dsh` floor, peers and engines are unchanged, and the package name, export surface, persisted identifiers and wire protocol are untouched. Upgrading from or rolling back to 0.4.20 needs no data migration in either direction.

### Other changes

- Version alignment: `version` in `package.json` moves from 0.4.20 to 0.4.21; satellites ship first and the main repository follows with the same number.
- The only version-dependent value baked at build time: `buildPackageVersion()` in `shared/tsdown.client.ts` reads `version` from `package.json` and bakes it as `__DSH_PKG_VERSION__` into the anonymous install heartbeat, so the baked value moves from 0.4.20 to 0.4.21; module bodies, export tables and type declarations come from unchanged sources and stay identical to 0.4.20.
- Release artifacts: `lib/` stays untracked (it is in `.gitignore`) and is rebuilt by the `prepare` script at publish time; this file is not in the npm `files` whitelist and does not enter the tarball.
- This release commit carries only `package.json` and `docs/release-notes/v0.4.21.md`.
